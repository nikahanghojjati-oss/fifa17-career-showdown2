## Deepened-understanding lessons preserved for the next developer

1. Source-first authority prevents historical-chat archaeology from silently reverting newer implementation.
2. Owner corrections and owner visual acceptance can supersede earlier developer assumptions even when automated QA is green.
3. Planning depth and dependency ordering have been a major force multiplier in this project; future developers should implement the defined milestone rather than repeatedly restarting architecture/planning.
4. Data safety requires transactional semantics, not merely an Import button.
5. An unsigned SHA-256 checksum detects changed/corrupt backup bytes but is not authentication/signing.
6. A future cloud adapter will require identity, revision/conflict, privacy/security and reliability foundations; it is not simply a different storage backend.
7. Local vanilla JavaScript remains a deliberate fit for the current static/local-first product; framework or TypeScript migration needs measured evidence, not prestige.
8. Public rankings remain conditional because manually entered FIFA 17 results are not inherently globally verifiable.
9. Visual quality must be judged in destination geometry. High source resolution alone does not guarantee useful subject composition.
10. Do not double-crop authored photographic derivatives blindly through generic responsive CSS.
11. Machine-green visual checks and owner art-direction acceptance are separate gates.
12. Never weaken a quality gate merely because it reveals an uncomfortable defect.
13. Performance budgets are architecture constraints; do not raise them merely to fit new eager code.
14. Preserve exact raw data during recovery work. Helpful normalization before a rollback snapshot can destroy the evidence needed for true restoration.
15. Continuous public handoff recording prevents context-limit recovery from becoming memory reconstruction.
