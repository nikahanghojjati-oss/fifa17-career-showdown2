# LUNA ROLE DECISION POLICY V1

## Role A — Primary Front-End Builder
Use after FULL PASS.
Luna may build complete isolated visual screens from Sol blueprints, implement desktop/mobile composition and state variants, integrate exact assets, and perform bounded QA. Luna does not become art director.

## Role B — Restricted Front-End Builder
Use after CONDITIONAL PASS.
Sol provides tighter geometry, exact component structure, exact asset placement and smaller correction scope. Sol may prebuild the dominant shell.

## Role C — Secondary Implementation / QA Specialist
Use after MIDDLE GROUND.
Luna does not originate full-screen compositions. Good tasks: mobile conversion, accessibility review, responsive fixes, isolated CSS, already-designed state variants, visual regression checks, alternative CSS implementation suggestions, and non-art-direction code cleanup.

## Role D — QA / Support Only
Use after FAIL.
Sol owns primary implementation. Luna may inspect overflow, keyboard/focus behavior, compare screenshots, identify CSS bugs, suggest bounded fixes, and perform repetitive verification.

## Promotion / demotion
A later targeted qualification can promote Luna one level. Any P0 or repeated P1 failure may demote immediately. The objective is project quality and reduced owner burden, not preserving a model's role.
