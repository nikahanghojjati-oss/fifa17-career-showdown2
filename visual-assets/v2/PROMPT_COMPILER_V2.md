# SHOWDOWN VISUAL — GENERATION PROMPT COMPILER V2

## Principle

Never prompt from vibe alone.

Every asset prompt is compiled from six blocks.

## Block A — identity truth

Use 2–4 curated identity anchors for the subject.

State:
- face shape
- hair
- beard/stubble
- age impression
- wardrobe continuity
- likeness requirement

Do not use another manager as an identity anchor.

## Block B — role semantics

State what the person is doing and why.

Bad:
"thinking pose"

Good:
"post-deadline transfer analyst reviewing a blank scouting sheet, torso turned inward toward the center operations board."

## Block C — composition geometry

Specify:
- body framing
- facing angle
- gaze direction
- hand roles
- prop allowance
- UI safe zone
- crop safety
- transparent / environment background

## Block D — style DNA

Include:
- black/gold cinematic football-manager world
- warm rim light
- graphite tailoring
- stadium-compatible contrast
- premium realistic-stylized rendering

Do NOT ask the model to render the entire application UI.

## Block E — negative constraints

For people:
- no extra fingers / limbs
- no identity drift
- no unreadable product UI
- no real club logos unless licensed/required
- no baked score/timer/state
- no irrelevant props
- no pose copied from a forbidden screen family

For environments:
- no live state text
- no exact score/timer
- no fake interactive controls
- no obstructive high-contrast detail in UI safe zones

## Block F — output contract

Specify:
- transparent PNG for compositable people/objects
- high resolution
- intended left/right placement
- minimum breathing room
- no text unless the asset itself is a stable decorative wordmark approved for rasterization

## Reference ratio

Use the smallest effective set:
- 2 identity anchors
- 1–2 style/pose references
- optionally 1 environment/composition reference

Too many references can average away identity and confuse the pose.

## Paired-character rule

Generate one identity-bearing character at a time, QA it, then generate the other.

Do not generate both managers together when the goal is reusable transparent pose assets.
