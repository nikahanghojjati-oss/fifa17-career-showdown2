# SOL SENIOR UI/UX WORKFLOW V4

## Role

Sol is not merely reviewing Luna.

Sol owns:
- product-to-visual translation
- art direction
- information hierarchy
- typography
- environment
- component grammar
- responsive strategy
- motion concept
- final visual QA

Luna is a restricted implementation specialist.

## Phase 0 — LIVE PRODUCT SYNC

Before touching visuals:
- resolve latest main
- inspect current DOM / JS / CSS ownership
- enumerate current user-visible states
- identify changes since the old visual proposal
- freeze a source anchor for this slice

Output:
LIVE_SCREEN_TRUTH_CARD

No screen skips this phase, including previously approved screens.

## Phase 1 — EXPERIENCE THESIS

Write one sentence:
"What should the player feel and understand within two seconds?"

Then define:
- narrative metaphor
- dominant object
- primary action
- information priority
- character role
- environment role
- motion role

Output:
EXPERIENCE_THESIS

## Phase 2 — REFERENCE DECOMPOSITION

Choose 2–4 references only.

For each, extract:
- composition
- typography
- light
- material
- density
- character staging
- motion idea

Also record what must NOT be copied.

Output:
REFERENCE_DECOMPOSITION

## Phase 3 — GOLDEN COMPOSITION BY SOL

Before Luna works, Sol creates the major composition.

For Level-A screens this means an actual browser-openable golden frame or equivalent rendered prototype, not prose alone.

The golden composition must establish:
- world/background exposure
- title system
- shell
- dominant object
- hero placement
- primary CTA
- material hierarchy
- spacing rhythm

States may still be incomplete at this stage.

## Phase 4 — BLIND VISUAL CRITIQUE

Render the golden composition at target viewport.

Do not read implementation notes first.

Ask:
- Does it look premium?
- Is the screen identifiable without labels?
- Does it feel authored rather than assembled?
- Does it belong to the same product?
- Is the football world visible?
- Is the typography unified?
- Is there a memorable visual idea?

If no, Sol revises before Luna sees it.

## Phase 5 — RESPONSIVE ART DIRECTION

Create separate composition rules for:
- wide desktop
- Chromebook/tablet
- mobile

Determine what disappears, stacks, crops, reorders or changes density.

Do not delegate responsive art direction to Luna.

## Phase 6 — MOTION STORYBOARD

For each meaningful transition define:
- trigger
- purpose
- duration band
- easing character
- reduced-motion behavior
- cancellation / non-blocking rule

Motion must support state or delight without slowing core play.

## Phase 7 — IMPLEMENTATION PACKET

Only now compile Luna's task:
- current screen truth
- exact asset IDs
- exact V3/V4 primitives
- golden composition
- geometry
- type roles
- environment recipe
- state matrix
- responsive rules
- motion rules
- forbidden changes
- QA matrix

Luna should not need aesthetic interpretation.

## Phase 8 — LUNA PRODUCTIONIZATION

Luna:
- implements state variants
- wires exact assets
- builds responsive layouts
- preserves product contract
- applies shared primitives
- runs bounded QA

Luna does not redesign the golden composition.

## Phase 9 — DUAL QA

A. VISUAL QA
- Premium Quality Bar V4
- browser renders
- comparison against golden composition

B. PRODUCT QA
- current source behavior
- privacy
- navigation
- state integrity
- accessibility

Both must pass.

## Phase 10 — OWNER REVIEW

Nik sees:
- browser render
- concise rationale
- what changed from current product
- any genuine unresolved design choice

Owner approval is visual authority.

## Phase 11 — LEARN AND PROMOTE

After approval:
- update design system only for genuinely reusable lessons
- update asset registry
- update current screen map
- archive superseded visual proposals
- do not declare other screens finished by analogy

## Work-order principle

Premium quality beats throughput.

One excellent screen that establishes reusable primitives is more valuable than six mediocre screens completed quickly.
