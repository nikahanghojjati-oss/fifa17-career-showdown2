# SOL — PREMIUM GOLDEN COMPOSITION WORKFLOW V5

This replaces prose-first screen delegation.

## STEP 1 — CURRENT PRODUCT FORENSICS

Resolve current main.
Inspect DOM + owning JS + CSS.
Enumerate:
- visible content
- actions
- states
- privacy
- errors
- empty/loading/waiting states
- responsive constraints
- module-injected controls

Freeze source anchor.

## STEP 2 — EXPERIENCE THESIS

Write:
"This screen should feel like ______ while letting the player ______."

Then define:
- dominant object
- emotional beat
- primary action
- attention path
- environment role
- character role
- information density
- motion beat

## STEP 3 — REFERENCE DECONSTRUCTION

Use no more than 4 references.

For each extract only:
- composition
- type
- material
- light
- density
- motion
- character staging

Never copy stale product content.

## STEP 4 — TYPE + GRID LOCK

Before component styling:
- choose V5 type roles
- define display size range
- define body/functional scale
- set spacing rhythm
- set central safe zone
- define dominant-object bounds

## STEP 5 — BACKGROUND-ONLY FRAME

Render the screen with:
- world
- light
- atmosphere
- no UI

Pass criteria:
- reads as Showdown world
- screen-specific mood visible
- safe zones remain usable
- mobile crop viable

## STEP 6 — CHARACTER / OBJECT STAGE

Add only:
- required heroes
- dominant object silhouette

Pass:
- eye goes to intended center
- heroes direct attention inward
- no pasted-on look
- lighting belongs to same scene

## STEP 7 — LIVE UI LAYER

Add controls using system primitives.
Do not create a container until grouping/elevation requires it.

Run BOX TAX:
For every rectangle ask, "What structural purpose does this box serve?"
If answer is "to organize things", try spacing/alignment first.

## STEP 8 — GOLDEN FRAME RENDER

Render wide desktop.

Blind review:
- does it look professionally art-directed?
- does it look expensive?
- would a viewer identify the screen story without reading every label?
- does it avoid generic AI UI?
- does it exceed the old 6/10 reference family?

If not, revise before delegation.

## STEP 9 — RESPONSIVE COMPOSITION

Create separate rules for:
- wide desktop
- Chromebook/tablet
- mobile

Design mobile from hierarchy, not from shrinkage.

## STEP 10 — MOTION MAP

Define only meaningful motion:
trigger / target / purpose / duration band / easing / reduced-motion behavior.

## STEP 11 — LUNA PACKET

Give Luna:
- frozen golden frame
- exact HTML structure expectations
- exact visual primitives
- exact assets
- state matrix
- responsive map
- motion map
- QA targets
- forbidden drift

## STEP 12 — FIDELITY DIFF

When Luna returns:
compare Luna render to golden frame before scoring functionality.

Any major visual degradation is Luna correction burden.

## STEP 13 — PRODUCT QA

Then verify behavior/state/privacy/navigation/accessibility.

## STEP 14 — OWNER REVIEW

Nik sees only a candidate that already passed Sol visual and product gates.
