# Season Results · Product truth

This truth sheet records the live Shared Season Results product on `main`. The visual build must preserve these routes, DOM hooks and behaviours while replacing only presentation.

### Entry routes

The production route intercepts two existing buttons when the shared Transfer Challenge is complete and not in replay mode:

1. `#continueFromTransfers` on the Transfer Challenge. It is decorated as `CONTINUE TO SHARED SEASON RESULTS` and opens Shared Season Results.
2. `#seasonPrimaryAction` on the Showdown dashboard. Its label depends on Results state and it opens the same Shared Season Results screen.

While opening, both controls can show `OPENING SEASON RESULTS…` and are temporarily disabled. The route calls the Results adapter, which refreshes authoritative state, then calls `navigateTo("seasonEntry")`. If the state is already `RESULTS_READY`, it also refreshes Shared Season Commit before returning.

The core route gate in `js/screens.js` gives the shared adapter direct authority for `seasonEntry` when `CareerModeProductionSharedSeasonResults.canRoute()` is true. Outside that authority, the legacy/local route only allows Season Results after the current local Transfer Challenge is complete.

Transfer replay is explicitly excluded: if `#transferChallenge` has `data-shared-transfer-replay`, the shared Results route does not open.

### Back behaviour

The visible Back button is not hard-wired to one page. `.backButton` clicks are captured by the centralized smart-back handler in `js/screens.js`.

For `seasonEntry`, legal Back targets are, in order, `dashboard` then `mainMenu`. The router first uses a valid target from screen history; otherwise it tries those legal fallbacks. The Shared Season Results browser audit specifically requires the Back button to stay visible after the first manager publishes and verifies that it returns to `#dashboard`.
