`cinematic background + characters + board`

to:
`inhabited football environment + deliberate camera + shared physical relationship + sharp live interface`

The current SV01 candidate remains evidence and a 7/10 baseline. It is not the reusable golden reference.

## 3. Accepted Astra findings

V10.1 adopts the following as active authority:

1. FIFA 17 contributes strong flat interface hierarchy, unequal rectangles, clear active states and condensed sporting typography.
2. The Journey contributes place, human viewpoint, camera logic, character relationships and consequence.
3. Showdown should use three presentation modes:
   - Orientation
   - Decision
   - Consequence
4. The interface should remain screen-aligned and readable even when the environment is dimensional.
5. Depth should come first from perspective agreement, occlusion, contact, relative scale, coherent light and material response.
6. A specific room can create more immersion than a generic stadium spectacle.
7. Character placement must express a relationship between gaze, posture, task and camera.
8. Mobile must preserve human rivalry identity, not merely keep a stadium crop after removing both people.
9. Initial implementation should be layered 2.5D + semantic DOM, not a full real-time 3D room.
10. The scene must pass as a still before motion is added.

## 4. Visual constitution

### Orientation
Question: where are we and what is next?
World is more visible than UI.
Use C1 Establishing Rivalry.

### Decision
Question: what must I do now?
Task is dominant but remains embedded in a believable room.
Use C2 Decision Desk by default.

### Consequence
Question: what happened and what follows?
Confirmed result/object becomes focal; world and human reaction support it.
Use C4/C5 as appropriate.

These modes style current product states. They do not create new phases.

## 7. Shared-space rule

A major rivalry screen fails V10.1 if Daniel, Nik and the task can be visually separated into unrelated poster elements.

The frame must make clear:
- where the viewer is
- what physical surface/threshold defines the room
- what Daniel is attending to
- what Nik is attending to
- what the task physically relates to
- where the key light comes from
- where bodies/props meet surfaces

Characters do not need to touch the UI.
They do need to inhabit the same camera and light system.

## 8. Interface rule

Live UI remains semantic DOM and visually screen-aligned.

The surrounding display housing, desk, wall, glass, physical frame or prop may use perspective.

Never skew form text merely to manufacture depth.

## 9. Depth order

P0 Far world — stadium/pitch/crowd
P1 Threshold — window/opening/beam
P2 Room — desk/chair/architecture
P3 Characters — Daniel/Nik/neutral props
P4 Near object — desk lip/display housing/foreground occlusion
P5 Task UI — live inputs/state/action
P6 Shell/status — navigation/recovery/session

Do not create seven image layers automatically.
Use only as many independent planes as materially improve the scene.

## 10. Lighting / material

Default:
- cool-neutral room ambient
- warm practical/key accent
- natural skin
- matte graphite structure
- brass only as priority/material accent
- gold strongest on primary action / selected state

A global gold tint is forbidden as a substitute for shared lighting.

## 11. Mobile rule

A phone is a closer view of the rivalry, not a miniature desktop.

At ~390x844:
- keep a compact scene/identity region
- keep explicit Daniel / Nik context
- preserve one spatial cue such as window reveal, desk edge or purposeful partial figure
- prioritize 16px+ form values and comfortable touch targets
- allow legitimate vertical scroll rather than shrinking essential text
- reduce/freeze scenery when the software keyboard is active

The V10 mobile pattern that removes both people and leaves a long empty stadium tail is retired.

## 12. Implementation direction

Preferred initial tier:
`layered 2.5D scene + semantic DOM + small presentation controller`

The controller consumes product state but never owns it.
All user actions continue through existing product handlers.

Full real-time room/character rendering is not justified as the starting requirement.

## 13. Golden-frame rule

A V10.1 golden frame must pass:

A. Spatial confidence
- clear place
- clear viewpoint
- 3+ meaningful depth bands
- contact-bearing near surface
- architectural threshold
- coherent light

B. Hierarchy and identity
- task leads
- world supports
- Daniel/Nik are correct and legible
- no generic equal-card treatment

C. Functional presentation
- only current states
- privacy intact
- semantic live controls
- enlarged text / touch / focus / software-keyboard plan

D. Restrained motion
- still frame already succeeds
- no decorative drift during input
- reduced-motion equivalent

E. Owner comparison
- exact baseline and proposal at matching viewport
- Nik judges spatial credibility, character integration, hierarchy, distinctive identity and mobile quality
- no internal score overrides owner calibration
