# Developer start: POS20

## Visual proposal branch gate

If the current task is visual proposal work or the current branch matches `visual/*`, read `00_VISUAL_PROPOSAL_GOVERNANCE.md` before doing anything else.

That file is a mandatory scope boundary. Visual sessions may study current `main` as read-only evidence and may build/refine proposal work on the isolated visual branch, but they do not own production integration. They must not merge, push, deploy, or otherwise integrate visual proposal work into `main` or the live Career Mode Showdown product. The senior Career Mode Showdown developer independently reviews, adapts, validates, and decides whether/how the proposal enters production.

When visual proposal work reaches a reviewable stopping point, use `docs/VISUAL_PROPOSAL_HANDOFF_TEMPLATE.md` to produce the senior-developer verification/integration handoff.

This visual gate limits execution authority; it does not replace POS20 reasoning, evidence discipline, testing expectations, or anti-spiral governance.
