# Hunt 1017 · Shared season flow across devices
Node available: yes — v24.19.0.
Source: gameplay/bug-list-1 at 315dcd51ef6f13d1d62f76ff509af118f539ddf4 (pinned read-only snapshot).
Scope: report and standalone repro scripts only; no game, test, Rules or workflow edits.

## Flow map
1. Setup must be SHOWDOWN_CONFIRMED (revision 6); Career Start must be ready.
2. Completed per-season Transfer Challenge unlocks the shared Season Results route.
3. Each manager reviews seven private facts; publishing creates an immutable role document.
4. Public Season Results goes from absent to COLLECTING rev 1 to RESULTS_READY rev 2.
5. Rival facts are read only after both roles have published; public metadata contains no result payload.
6. Production publication serializes requests, blocks overlapping writes and retries one stale revision.
7. League projection has a separate preflight transaction; denied races retry and re-read public revision.
8. The coordinator commits the exact two-result snapshot, producing COMMITTED rev 1.
9. The combined coordinator button then acknowledges separately; the rival acknowledges on its device.
10. Both acknowledgements make ACKNOWLEDGED rev 3; cached acknowledged commits stop polling.
11. Canonical scoring reads the acknowledged immutable commit; it does not write the local Save.
12. Shared History rebuilds a contiguous accepted prefix, verified scores and fixed manager bindings.
13. Multi Season derives acceptedSeasons and SEASON_READY or SHOWDOWN_COMPLETE from that prefix.
14. Continue advances a page-memory cursor only after visible history, then opens the next transfer.
15. Reload resume restores that cursor from remote authority; total lengths are 1, 3, 5 or 10.
16. Local Reconciliation observes Connected Rivalry; if absent at terminal, it publishes and re-reads.
17. Final Reconciliation combines terminal progression, full history and exact local binding.
18. The automatic preview is read-only; explicit Candidate C Apply remains outside the gameplay UI.
19. Terminal Close accumulates per-season proof, then closes the rivalry and exact session together.
20. Final Winner uses reconciled totals or the persisted closed witness; equal totals produce a draw.

## Findings

### H1017-1 A refresh discards the pending terminal-close recovery state
severity: S2 (wrong recovery state shown)
status: CONFIRMED (failing Node repro; production adapter with deterministic provider fakes)
where: js/productionSharedTerminalClose.js:119-138 (ptcRefreshNow/ptcRefresh), :189 (ptcClose), :198-200 (ptcRetry), :232-253 (poll/events)
steps: 1. Finish a 10-season Showdown and reach READY. 2. Close returns an ambiguous unavailable response while the rivalry still reads open. 3. Let the regular refresh run, or call refresh(). 4. Try the advertised same-close retry.
expected: Preserve RECOVERY_PENDING and its exact witness until a verified closed read resolves it or an explicit same-witness retry resolves it.
actual: The open read falls through to a fresh READY intent. retry() now returns TERMINAL_CLOSE_RECOVERY_REQUIRED. If the session has changed, this path can prepare a replacement session witness rather than keep the unresolved one. The repro proves the state loss with the session unchanged; the replacement-session consequence is a code-path inference.
repro: sweeps/repro/hunt-1017-terminal.cjs, first test. Output: "H1017-1: phase after poll = READY ; retry = TERMINAL_CLOSE_RECOVERY_REQUIRED"; assertion READY !== RECOVERY_PENDING.
fix idea: While recovery is pending, allow refresh to resolve a matching persisted closed witness; preserve the held intent for every unresolved/open read instead of rebuilding READY.
rulebook/panel check: Rule Book connection/recovery promises continued play through recovery. The scoring panel has no close-retry rule; scoring math is unaffected. The precise same-witness recovery contract is also explicit in this adapter.

### H1017-2 Retry invokes an old Showdown close after the active Save changes
severity: S1 (mutates shared state for a context that is no longer active)
status: CONFIRMED (failing Node repro proves the stale provider invocation; no real remote write was made)
where: js/productionSharedTerminalClose.js:204-208 (ptcRetry), :160-162 (ptcAccepted)
steps: 1. Enter RECOVERY_PENDING for Save A. 2. Retry and hold its awaited provider.read. 3. Switch the active Showdown to Save B and another rivalry. 4. Resolve the old read as open.
expected: Re-check the request key after the awaited read and return TERMINAL_CLOSE_CONTEXT_CHANGED before calling provider.close for A. Re-check again after the close result before forgetting any session.
actual: provider.close is invoked a second time with A's old rivalry and witness despite the active context being B. ptcPublish's eventual context check protects the rendered state, but it runs after the provider call. A successful result would also call forgetSession without a current-context check; that side effect is inferred from ptcAccepted.
repro: sweeps/repro/hunt-1017-terminal.cjs, second test. Output: "H1017-2: provider close calls = 2 ; retry wrote old rivalry = true"; assertion 2 !== 1. Here "wrote" means the deterministic fake received the old close request, not a Firestore write.
fix idea: Carry the exact request/generation through every await in retry; stop before the mutation or session cleanup when it changes, as the normal close path already does.
rulebook/panel check: Recovery belongs to the same remembered career and fixed Showdown, not a newly selected Save. Scoring-panel values are unchanged; the failure is stale-context mutation.

### H1017-3 Closed Final Winner cannot join its otherwise available trophy history
severity: S2 (incomplete final state shown despite supplied accepted history)
status: CONFIRMED (failing pure Node repro using actual result/commit/history/final/terminal protocols)
where: js/seasonFinalV10.js:15-25 (finalFrame); js/sharedTerminalClose.js:9,26-29 (INTENT_KEYS/tcPrepare)
steps: 1. Derive a complete 10-season history and final reconciliation. 2. Produce the verified terminal intent with the real protocol. 3. Supply finalFrame with that CLOSED witness, no live reconciliation, and the same authoritative accepted history.
expected: A completed winner frame can retain trophy attribution from independently verified history for that exact completed Showdown.
actual: Before close the frame is ready. In the terminal-witness fallback it is always partial with trophies omitted, because the join requires p.acceptedRevisionKey === r.acceptedRevisionKey, and the terminal intent's exact schema has no acceptedRevisionKey. Supplying full matching history does not help. Winner and totals remain correct.
repro: sweeps/repro/hunt-1017-closed-frame.cjs. Output: "H1017-3: before=ready; closed=partial; trophies=false; acceptedRevisionKey in witness=false"; assertion partial !== ready.
fix idea: Give the closed frame an independently verified completed-history authority that can establish the history binding, or retain the verified reconciliation alongside the witness. Do not simply remove the history-integrity check.
rulebook/panel check: Earned league/cup/Champions League trophies stay earned across the fixed Showdown. The scoring panel agrees with the control fixture; this is a missing-data join, not a scoring discrepancy.

### H1017-4 A new shared season inherits the previous season's editable facts
severity: S2 (wrong season state shown; copied facts can be immutably republished)
status: CONFIRMED (failing Node repro with minimal DOM fake and the real production adapter)
where: js/productionSharedSeasonResults.js:120-128 (pssrRenderEntry/pssrRender), :157-159 (cursor tick); js/productionSharedSeasonResults.js:152-153 (pssrOpen)
steps: 1. Show a published season-1 result with position 1, 100 points/goals and earned achievements. 2. Advance the shared cursor to season 2 on the same page. 3. Refresh/open Results with season 2 ownResult null.
expected: Reset all seven facts when the exact shared season/manager context changes; retain typed drafts only within that same context.
actual: The heading/view become season 2 and inputs become editable, but all prior values and checked achievements remain. Changing renderedContextKey only clears draft. pssrRenderEntry writes published values when present and never clears fields for a new unpublished season. Shared open() navigates directly, bypassing the legacy openSeasonEntry reset.
repro: sweeps/repro/hunt-1017-season-fields.cjs. Output: "H1017-4: new season=2; position=1; ChampionsLeague=true; editable=true"; assertion "1" !== "".
fix idea: At a confirmed new season/role context, clear fields before rendering its own-result/draft state. Do not clear same-context user input on polls.
rulebook/panel check: Manual FIFA 17 results and trophies are per season. Retaining last season's trophies as checked inputs in a new season conflicts with that boundary. The score weights themselves match the panel.
