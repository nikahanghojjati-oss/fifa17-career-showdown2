## Bug
On the Season Results screen the league-points box accepts up to 114 in every league. 114 is the maximum for a 20-team league (19 opponents x 2 games x 3 points). The Bundesliga has 18 teams, so its maximum is 102 (and its position maximum is 18). The game server already uses the real league size, so a Bundesliga manager who types 103 to 114 passes the screen's check and is then rejected.

The cause is in `js/productionSharedSeasonResults.js`, `pssrTeamCount()` (line ~85): when it can't find the league's club list it falls back to 20.

## Read (only these)
1. `js/productionSharedSeasonResults.js`: `pssrTeamCount`, `pssrReadForm`, and where `view` is set (lines ~75-95, ~145-155).
2. `js/sparkSharedSeasonResults.js` lines ~100-140: the server reads the league size from the shared catalog (`catalogModule.catalog[setupState.leagueId].length`) and stores it as `teamCount` in the public season-results state, which the screen receives in `view.state`.
3. `js/sharedShowdownCatalog.js`: the club lists (bundesliga has 18).

## The change (one file of game code, `js/productionSharedSeasonResults.js`)
- `pssrTeamCount()` uses, in this order: the `teamCount` the server already sent in `view.state` (when it is a whole number from 2 to 20), then the shared catalog's club list for the confirmed league, then 20.
- DEFAULT: if the league id is stored under a different field than the one the function reads today, read it from the same place the server does (the confirmed setup's `leagueId`). Change nothing else on the screen.
- Keep every message text as it is (they already print the computed maximum).
