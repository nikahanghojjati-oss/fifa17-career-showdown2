## Why
PR #861 (JOB-1827, which contains JOB-1826 / #852) cuts the reads while both managers wait. Claude's check found three problems
that must be fixed before it can merge. Full report: `/mnt/project-files/gameplay/r76/verify/PR-861.md` (copy below).
1. **Blocking: session expiry by the clock is never shown while waiting.** pjr finds expiry only by comparing `expiresAtEpochMs`
   with the clock. No production code writes an EXPIRED session doc (`expireSession` has no caller), so no listener fires. The PR
   gates pjr's interval behind `waitingListenerHealthy()` (`js/productionSharedJourneyReconnect.js:197`). The PR's test passes only
   because its fixture writes `status:"EXPIRED"`. Clock-only probe: >90000 ms, 12/12 FAIL on the PR head; 3000 ms PASS on r75.
2. **The fast 3 s poll window never ends.** `...<FAST_POLL_WINDOW_MS||Boolean(root.CareerModeFirestoreBudget)` at
   `js/productionSharedSeasonCommit.js:245` and `js/productionSharedSeasonResults.js:202`. The budget layer is always present, so
   when the listener is unhealthy the 3 s checks run for the whole wait (40 reads/min flat, r75: 40 then 24).
3. **The first delivery wakes everything.** `serial` starts undefined, so the first snapshot of every context listener counts as
   a change and runs forgetContext plus a forced-fresh round in every owner. Attach costs 31-37 reads and each tab return 36-44
   (r75: 0-1 and 6-8). The `watching` key also rebuilds every listener on the Results-to-Commit switch.

## What to do

   add a clock-only expiry case, `w.setRemote({...w.remote(),expiresAtEpochMs:start-1})` with NO server write; it must show the
   recovery banner within the r75 deadline (3000 ms). Add a cost case: attach the waiting screen with a healthy listener and count
   reads on first delivery and on one tab hide/show; it must be <= 2 and <= 8 (r75 levels). Add a case that the 3 s fast checks
   stop after `FAST_POLL_WINDOW_MS` when the listener is unhealthy. Show each FAILS on the PR head.
2. **Fixes.**
   - `js/productionSharedJourneyReconnect.js`: do not let `waitingListenerHealthy()` silence pjr's interval (the clock check reads
     nothing when the session is not exact-active), or skip only while `now < remote.expiresAtEpochMs`.
   - `js/productionSharedSeasonCommit.js:245` and `js/productionSharedSeasonResults.js:202`: drop `||Boolean(root.CareerModeFirestoreBudget)`.
   - `js/productionSharedSeasonCommit.js` `psscWaitContext`: treat the first server snapshot per path as the baseline (no wake).
     Wake once, without forgetContext, when `pending` first empties. Call forgetContext only on real content changes. Leave
     `watching` out of the listener key so the Results-to-Commit switch keeps the listeners.
   - `js/productionSharedTerminalClose.js`: add the same `wakePending` flag pjr has, so a context wake that arrives while ptc is
