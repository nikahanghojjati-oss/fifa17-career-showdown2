## What to build
The picture-free half of the **Career Statistics** screen, in one pull request. It needs no pictures and no browser; reason from the CSS and JavaScript you read (there is no read limit). The desktop mockup match, adopted studies and polish are the WORK job 1706, which runs after this PR merges.

1. **Every size.** Check the screen at 360x640, 375x553, 393x660 (phones upright), 740x360 and 844x390 (sideways), 768x1024 and 820x1180 (tablets), 1280x650, 1366x768, 1920x1080 and 2560x1080. Fix what is actually wrong: nothing cut off, no horizontal scroll, no text over text, no button off screen, the primary action visible at first view, one page scroll only (`main` is the only scroller), tap targets at least 44 px on touch sizes.
2. **The standing checks** (fix only what is actually off; CSS only unless a line says otherwise):
- **Long names:** Put the longest realistic texts into this screen in your head (22 letter club name, 14 letter manager name, 3 digit scores, 7 seasons) and make sure nothing overlaps, overflows or pushes a button away. Use ellipsis, wrapping or smaller text where a name sits in a fixed box.
- **Tap targets:** Every button, tab and link must be at least 44 by 44 CSS px on touch screens (pointer: coarse or max-width 760px), with at least 8 px between neighbours. Fix the ones that are smaller. Desktop with a mouse must not change.
- **Keyboard focus and reduced motion:** Every control needs a visible focus ring from the keyboard (:focus-visible), and animations must stop or shorten under prefers-reduced-motion. A mouse or finger user sees no change.
- **Text contrast:** Find text and background pairs below 4.5 to 1 (3 to 1 for text of 24 px or larger). Fix the worst five by changing the text colour only, never the artwork. List the pairs in the results file.
- **Picture descriptions and labels:** Every meaningful image needs a short alt text, every decorative one alt="" or aria-hidden, every icon-only button an aria-label. Change only attributes, never visible text or layout.
- **Loading state:** Look at what the screen shows while its data loads. It must show something calm and readable (no empty frame, no half-drawn layout, no jump when data arrives). Fix with CSS, and with markup classes only if needed. Do not change any text.
- **Empty state:** Look at what the screen shows when there is no data yet (a brand new career, no trophies, no seasons). It must look finished, not broken: centred message, correct spacing, no empty boxes with borders. Do not change any text.
- **Error and retry state:** Look at what the screen shows when something fails to load. The message and its retry button must be fully visible and tappable at phone and desktop sizes, not hidden behind other layers. Do not change any text or logic.
- **Hover-only effects:** Find anything that is shown or usable only on :hover. Make each also work by touch: apply the style on :focus-visible and :active, or show it always when pointer: coarse.

Presentation only: every live word, id, tap order and number stays as the live screen has it. Scope each fix with media queries so sizes you did not touch stay identical. DEFAULT: if the screen is already clean, change nothing and commit only the status file with `no change needed` and the three risks you checked.

## Layout rules (lead's fixes from the browser checks; follow all of them)
- `main` is the only scroller; html/body overflow does nothing.
- (a) Hide old hero nodes by class with `display:none` inside your media query, **never by img `src`**. Keep exactly one hero.
- (b) Anything you size must shrink (for example a `clamp(...)` against `100svh` minus the card and buttons) so the card and the primary action fit the first view.
- (c) No `overflow-wrap:anywhere` on short labels; give the label enough width and let whole words wrap.
- (d) Hiding old images is not enough: also reset the space they reserved (`--sr-hero` / stage plate layers and the title-block margin).
