## Bug
The 15-minute transfer countdown can show different seconds on the two phones. Your own recheck (job 1057, `project-documents/gameplay-factory/reports/SOL_LEADS_S3_S4_RECHECK.md` on branch `qa/sol-leads-recheck`) found the cause in `js/productionSharedTransferChallenge.js` `pstcEnsureServerClock` (lines ~58-73):
- it takes the sign-in token's `issuedAtTime` as the server time, but pins it to the moment the reply **arrived**, so each phone's network delay is lost;
- `issuedAtTime` is a date string with whole seconds only, so each phone is also up to one second early.

## Read (only these)
1. `js/productionSharedTransferChallenge.js` lines ~50-75 (`pstcMonotonicNow`, `pstcClockReady`, `pstcAuthoritativeNow`, `pstcEnsureServerClock`) and `pstcRenderTimer` (~line 225).
2. `tests/contracts/shared-tap-race-contracts.cjs` line ~53 and `tests/contracts/fewer-taps-contracts.cjs` line ~126: they fake `getIdTokenResult` with `issuedAtTime:new Date().toUTCString()`. Your change must keep working with that fake.

## The change (one file of game code)
In `pstcEnsureServerClock` only:
- Read `pstcMonotonicNow()` just **before** `await user.getIdTokenResult(true)` (call it `requestPerformanceMs`) as well as after it (`receiptPerformanceMs`, already there).
- Pin the server time to the middle of the round trip: `clockPerformanceMs = (requestPerformanceMs + receiptPerformanceMs) / 2`.
- Add half a second to `issuedAtEpochMs` when its milliseconds part is exactly 0 (a whole-second value), to centre the rounding: `clockServerEpochMs = issuedAtEpochMs + (issuedAtEpochMs % 1000 === 0 ? 500 : 0)`.
- Keep `clockRefreshPerformanceMs = receiptPerformanceMs`, the five-minute refresh, every error message and every other line unchanged.
- DEFAULT for anything else: change nothing.
