## The bug
The free plan allows 50,000 reads a day for both players. JOB-1824 (PR #851, `reports/firestore-meter/R76_FIRESTORE_METER.md`,
table "Rules lookups and idle cost") measured what the game reads while **both managers just wait** with the tab open, which is
most of a real season (they are playing FIFA):

| Wait screen, both visible | Game reads/min | Rules lookups/min |
| --- | --- | --- |
| Showdown Home | 9.1 | 149 |
| Standings | 9.8 | 158 |
| Season Results | 23.6 | 448 |

Writes while waiting were 0, and a hidden tab already reads 0. An hour of waiting costs about 850 game reads plus about 15,000
Rules lookups, more than a whole season of play. Nik's rule (12 Oct) is: **partner waits use a live listener on the one thing
awaited, with the 3 s check only as a backup if the listener drops.** The measured rates show checks still repeating while the
listener is healthy.

## Goal
While both managers wait on Home, Standings or Season Results and the listener is healthy: **at most 1 game read per minute per
manager** on each screen (listener deliveries when something really changes don't count against this), and no repeating
transactions. When the partner acts, the other screen still updates in **1 to 3 seconds**, exactly as today. When the listener
errors or is detached, the existing 3 s backup takes over until it is healthy again.
