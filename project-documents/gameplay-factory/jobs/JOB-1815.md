## The suspected bug (unsure; prove it first)
From audit PR #736 and the r76 bug inventory:
(a) the shared-journey guard can keep blocking local draws (SPIN LEAGUE / club draw) because an old per-tab `sessionStorage`
marker overrules a saved state that says setup is no longer pending; and (b) it may let a local draw through for a moment
after a reload, before the Save Library is ready.
Code: `js/productionSharedJourneyGuard.js:18-33` (marker fallback) and `:44-50`; the marker is cleared at
`js/productionSharedJourneyEntry.js:122,154` and `js/persistentNikDanielPair.js:188`. Every path that sets the marker seems to
clear it in the normal flows, so this may not be reachable.

## What to do
1. Write a browser audit `tests/browser/shared-journey-guard-marker-audit.cjs` with two cases:
   (a) start a Shared Showdown setup, delete the Showdown from Settings in the SAME tab (DELETE CURRENT SHOWDOWN), start a local
   Showdown and press SPIN LEAGUE: it must not be blocked;
   (b) with a shared Showdown in setup, reload and press SPIN LEAGUE as early as the button is clickable: the local draw must
   stay blocked (no local league drawn).
   Use the patterns in `tests/browser/shared-showdown-setup-audit.cjs` and `tests/browser/settings-offline-save-library-editor-audit.cjs`.
2. Run it on the base. If both cases pass, the suspicion is not reachable: open the PR with only the audit and write
   `NOT REACHABLE` with the evidence. If a case fails, find the cause (file:line), fix it in
   `js/productionSharedJourneyGuard.js` (and only if needed the two files that clear the marker), and show the audit passing.
3. Never add new `sessionStorage` use; removing a dependency on it is fine.

## Proof required
The audit output on the base and after; `node tests/browser/shared-showdown-setup-audit.cjs`,
`node tests/browser/settings-offline-save-library-editor-audit.cjs`, `node tests/browser/connected-account-settings-audit.cjs` pass.
