## Why
Every r76 bug fix is proven with the CE2PG two-player emulator run (Daniel and Nik play a whole Showdown in two browsers
and every History, Career Stats, Trophy Room and Legacy figure is recomputed and compared on both). The harness was written
on release r74 and lives only on branch `gameplay/ce2pg`. This job puts it on the r76 base and records the baseline that later
jobs compare against.

## What to do
1. Copy the harness as described below and add it to your branch **as a committed file** (this job is the one exception):
   `tests/browser/ce2pg-journey.cjs`. Do not change its checks. You may only fix things that stop it starting on this base
   (paths, ports, a renamed element id); list every such edit in the PR body with the reason.
2. Run, one after another (not in parallel): `CE2PG_SEASONS=3 CE2PG_RUN=1`, `CE2PG_SEASONS=3 CE2PG_RUN=2`,
   `CE2PG_SEASONS=10 CE2PG_RUN=3`.
3. Commit the three JSON reports (not the screenshots) as `test-results/r76-baseline/ce2pg-<seasons>-<run>.json` (create the
   folder; `git add -f` if ignored).
4. In the PR body, write a table per run: finished yes/no, minutes, history checks passed/total, number of lock timeouts (409),
   number of Rules errors ("rules-denied-commit" and "evaluation error" lines) with the first message of each kind, and which of
   these known bugs you saw (by number): 1 REVIEW SEASON hidden on the Champion screen; 2 Home tile/header chip stuck on
   "Season 1 of N"; 3 Standings THIS SHOWDOWN stuck on "Loading standings."; 4 Rivalry Statistics stuck loading; 5 BACK TO
   SHOWDOWN HOME lands on the dashboard; 6 phone Trophy Room ranks/records missing; 7 final reconciliation cells empty; 8 Rules
   expression limit on the close / setup write refused.
5. Add `npm run` nothing; don't wire the harness into CI.

No new contract test in this job (the harness is the test). The "Reproduce/Fix" order does not apply; the runs are the work.

## How every r76 Codex job works (read once, follow exactly)

**Start.** `git fetch origin gameplay/bug-list-1 && git checkout -B codex/job-1802-ce2pg-baseline FETCH_HEAD`. The base is release r75 (the live game).
Install with `npm ci` if `node_modules` is missing. Chromium for the browser tests: `tests/support/chromium-runtime.cjs`
downloads it to `/tmp/cms-chromium-runtime`, or set `CMS_CHROMIUM_PATH` to an installed Chromium.
Serve the game for browser tests with `CMS_TEST_PORT=4511 node tests/support/static-server.cjs &` and pass
`CMS_BASE_URL=http://127.0.0.1:4511/`.

**CE2PG (the two-player emulator run).** Copy the harness without committing it:
`git fetch origin gameplay/ce2pg && git show FETCH_HEAD:tests/browser/ce2pg-journey.cjs > tests/browser/ce2pg-journey.cjs`.
Run: `CE2PG_SEASONS=3 CE2PG_RUN=1 CMS_BASE_URL=http://127.0.0.1:4511/ node tests/browser/ce2pg-journey.cjs`. It starts the
Firebase Auth and Firestore emulators itself (`npx firebase-tools@15.28.1`, needs Java 17+) on a demo project; it never touches
production. Results: `test-results/ce2pg-<seasons>-<run>.json` plus screenshots. A 3-season run takes about 15 minutes, a
10-season run about 25. If the emulator cannot start in your environment, say so in the PR body and use the targeted browser test
named in the job instead. Do not commit `tests/browser/ce2pg-journey.cjs` or `test-results/` (unless the job says so).

**Order of work (always).**
1. **Reproduce first.** Show the bug on the unchanged base: the failing test output, or the CE2PG JSON lines, or a screenshot.
2. **Find the cause.** Name the file and line, and quote the 1-5 lines responsible.
3. **Write the test that fails.** One new test file named in the job (plain Node + `node:assert`, or a small browser audit
   using `tests/support/chromium-runtime.cjs` like the files next to it). Run it on the base: it must FAIL. Keep the output.
4. **Fix** with the smallest change. Run the new test again: it must PASS.
5. **Run the checks** listed under *Checks* and paste the last lines of each in the PR body.

**Registering a new test** (contract tests under `tests/contracts/` only; browser audits are not registered):
1. `POS20_SUPPLEMENTAL_PRODUCT_TESTS.json`: one entry at the END of `tests`, same shape as the last entry:
   `{"path": "tests/contracts/<file>.cjs", "patterns": ["^<changed js file, regex-escaped>$", "^tests/contracts/<file, regex-escaped>$", "^POS20_SUPPLEMENTAL_PRODUCT_TESTS\\.json$"]}`.
2. `tests/operations/pos20-control-plane.test.mjs`: add `const <camelName>Contract='tests/contracts/<file>.cjs';` after the last
   `const ...Contract=` line, and append `<camelName>Contract` as the LAST item of `expectedSupplementalContracts`. Nothing else.

**Never.** Never edit, delete, skip or loosen an existing test. Never push to `main`, `gameplay/bug-list-1` or any branch but
yours; never merge; never force-push. Never edit `index.html`, `service-worker.js`, `manifest.webmanifest`, the release
version, `.github/`, `scripts/`, `tests/fixtures/`, `visual-assets/`, or any `firestore*.rules` file. Never change how a screen
looks (colours, sizes, positions, pictures, fonts, lighting): visual work is release r77. Never touch the no-flash rules:
`data-v10-pending`, `data-v10-reveal`, `data-v10-decoding`, `prefers-reduced-motion` blocks in `css/v10Shell.css`,
`data-sd-enter` in `shared/motion.css`, picture preload/decode code, or startup order. Never add a timer, interval or poll that
reads Firestore, and never shorten an existing one: the free daily limit is tight (budget: at most 800 reads and 600 writes per
two-player season). Never use sessionStorage. Never deploy anything or use real Firebase projects.
