## Bug 1 (V3): the rivalry summary names a club whose pack is still sealed
In `js/productionSharedShowdownPresentation.js`, `ssjpFillConfirmation` writes both club names into the visible summary before `ssjpAnimatePacks` has opened the second pack. At stage `manager-one`, the packs show `["West Ham United","?"]` but the summary already shows `["West Ham United","Southampton"]`.

Fix: each manager's club name (and club identity styling) appears in the summary only once that manager's pack is revealed. Before that it shows "?". Final state and timing after both reveals must stay the same. Do not hide or reorder any screen.

Repro (must pass after): `CMS01-codex-1006-2349-sealed-club.cjs`. Also run `node tests/contracts/shared-showdown-polished-presentation-contracts.cjs`.

## Bug 2 (V5): restore on an empty device ignores Keep current
In `js/restore.js` `createCareerModeRestorePlan`, when `destinationIsClean` is true (around lines 144-180), the backup save library is restored even when the player chose Keep current for every item. An all-Keep-current apply on an empty device returns `{"gamesRestored":1}`.

Fix: Keep current always means keep what this device has, even when it is empty. An empty device stays empty, and the result reports nothing restored. "Use backup" choices behave as today. The non-empty case is already fixed (JOB-1027); do not change it.

Repro (must pass after): `codex-1006-1312-keep-empty.cjs`. The fixed sibling `codex-1006-1312-keep-current.cjs` must still pass. Also run `node tests/contracts/restore-plan-contracts.cjs` and `node tests/contracts/hunt-1019-restore-career-contracts.cjs`.
