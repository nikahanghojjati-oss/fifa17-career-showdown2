## The bug
During a shared Showdown (after season 1, before the close), Standings' **THIS SHOWDOWN** view stays on "Loading standings."
CE2PG counted it 92 times across 11 runs on r74 and saw it again on r75. The **HEAD-TO-HEAD** tab is also not visible or not
clickable there. After the close, the numbers are right.

## Where to start
- The text comes from `visual-assets/v10_1/standings/app-strings.json` (key `loading`), shown by Team V's screen module in
  `visual-assets/v10_1/standings/` when the data it is given has no rows. That folder is FROZEN (never edit it): the fix
  belongs in the glue that feeds it data, `js/careerScreensV10.js` (search `standings`), and the shared readers it uses
  (`js/sparkSharedMultiSeasonProgression.js`, `js/sparkSharedHistoryConvergence.js`, `js/sparkCompletedShowdownReader.js`).
- Find what the view waits for (a promise, an event, a shared read) and why it never arrives mid-Showdown. Typical causes:
  waiting for a terminal/closed record that only exists after the close, a read that throws and is swallowed, or a render that
  only runs on an event that already fired before the screen opened.
- Do NOT fix it with a timer or a poll. Use the data the screen already has (local committed seasons or the shared commits the
  game already read), or listen to the same event the Season Results screen uses.

## Test to add (must fail on the base)
Prefer a contract test `tests/contracts/standings-this-showdown-midway-contracts.cjs` (vm sandbox with the minimal fakes) that
renders THIS SHOWDOWN with 2 committed seasons of a 5-season shared Showdown and asserts rows appear instead of the loading
text, and that the HEAD-TO-HEAD tab is present and enabled. If a contract test is impossible, write a browser audit
`tests/browser/standings-this-showdown-midway-audit.cjs` instead.

## Proof required
New test fails on the base, passes after; CE2PG 3-season run: "Loading standings." count 0 mid-Showdown, Standings figures
still correct. Also `CMS_CHROMIUM_MULTI_CONTEXT=1 node tests/browser/shared-history-convergence-audit.cjs` and
`CMS_CHROMIUM_MULTI_CONTEXT=1 node tests/browser/shared-multi-season-progression-audit.cjs`.

## Exact pointers (from Claude's standing-bug inventory of r75; confirm by reading)
Strong hypothesis from the bug inventory: `js/sharedActiveShowdownAdapter.js:33-35` uses the cached History projection only when its `acceptedSeasons` matches, and `:66` sets `classification="loading"` otherwise; the Standings frame copies that status in `js/seasonFinalV10.js:202-216` and reads cached state only at `:252-256`. Since r75 cut background checks, nothing refreshes the projection mid-Showdown. Fix direction: build the THIS SHOWDOWN rows from the committed seasons the adapter already has when the projection lags (or refresh the projection once on the same event the Season Results screen already handles), never with a timer. This job OWNS `js/sharedActiveShowdownAdapter.js`; JOB-1809 depends on it.
