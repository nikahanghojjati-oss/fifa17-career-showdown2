## Bug
Refreshing halfway through Signing Entry clears the rows a manager has typed but not locked (player name, league, nationality). Locked signings and verdicts survive because they are shared, but the draft is lost. `js/productionSharedTransferChallenge.js` `pstcResetForContext` clears both roles and nothing stores the draft.

## The change
- Save this manager's own unlocked signing rows on this device while they type, in `localStorage`. Key them by rivalry id, season number and manager role, e.g. `cms.signingDraft.v1:<rivalryId>:<season>:<role>`.
- On reopening the same rivalry, season and role, refill the empty rows from the draft. Never overwrite a row that already holds shared (locked) data.
- Clear the draft when that manager locks their signings, when the season changes, and when the rivalry changes.
- Never save or show the rival's rows. Never send the draft to Firestore. Do not use `sessionStorage` anywhere (Remote Joining rule).
- Keep the 80-character name limit and every existing validation.

Repro (must pass after): `CMS03-codex-1006-2238-draft-reload.cjs` (the name comes back as `Paulo Dybala`, not `''`). Also run `node tests/contracts/shared-transfer-challenge-contracts.cjs` and `node tests/contracts/studio-z-contracts.cjs` if present.

## Proof
Add `tests/contracts/job-1050-signing-draft-contracts.cjs`: the draft is restored for the same rivalry, season and role; it is cleared on lock; it is not restored for another season or role; and the code never writes the rival's rows or uses `sessionStorage`.
