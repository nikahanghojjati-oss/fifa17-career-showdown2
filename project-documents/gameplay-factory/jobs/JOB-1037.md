# JOB-1037 · Career history: never-joined codes and an unknown current Showdown no longer break Legacy, Trophy Room and Career Statistics

## What players see (live r63)
After a finished one-season Showdown, back on Showdown Home: Trophy Room says "Some Showdowns could not be read. Showing 1 of 4", Career Statistics says "Career history unavailable", Legacy spins on "Loading your Showdown history…". All three screens use one loader: `rlLoadCareerModel` in `js/rivalryLegacyV10.js` (career index → `js/sparkClosedShowdownCareerLoader.js` → `js/sparkCompletedShowdownReader.js` per Showdown → `js/sharedClosedShowdownAdapter.js` → `sharedCareerAnalytics.buildCareerModel`).

## Root causes this job fixes (verified by the lead on the Firestore emulator with production Rules)
1. **Never-joined codes poison the career.** A Showdown enters Daniel's career index when he creates the pairing code (`js/persistentNikDanielPair.js` ~170-173), before Nik joins. Such a rivalry has only one entry in `authorizedAccountIds`. `js/sparkCompletedShowdownReader.js` checks the two-manager binding (~line 55, `authorizedAccountIds.length` must be 2; applied ~139-142) **before** it looks at `connectionState`, so it returns `unavailable / COMPLETED_NOT_A_MANAGER` forever, even after the code is abandoned. `js/sharedClosedShowdownAdapter.js` (~54) turns that into an unavailable row and `js/sharedCareerAnalytics.js` (~155) marks the whole career partial ("1 of N readable").
2. **An unknown or still-loading current Showdown hides all closed history.** `js/sharedActiveShowdownAdapter.js` (~66) classifies the current Showdown as `loading` after a reload on Home, and `js/sharedClosedShowdownAdapter.js` (~82) then makes the **whole** career `loading` (screens spin forever). If the current Showdown is `unavailable`, the adapter (~72) marks **every** not-closed indexed Showdown unavailable (`CLOSED_CURRENT_UNKNOWN`).

## The change
- `js/sparkCompletedShowdownReader.js`: decide what a rivalry is from `connectionState` (and the Terminal Close witness) **before** the two-manager check. A rivalry that never had two managers (never joined; open, or closed by abandon) is not a career Showdown: give it a distinct status (for example `never-started`) instead of `unavailable`. Keep every existing check for real two-manager Showdowns exactly as strict as today (a stranger or forged rivalry must still be unavailable/denied).
- `js/sharedClosedShowdownAdapter.js` and `js/sharedCareerAnalytics.js` (only if needed): `never-started` Showdowns are left out completely: not shown, not counted in "N of M", and they never make the career partial.
- `js/sharedClosedShowdownAdapter.js` and `js/sharedActiveShowdownAdapter.js`: a current Showdown that is `loading` or `unavailable` affects **only its own row**. Terminal-Closed Showdowns are always read and shown as completed. Only the current row may show as pending.
- Do not change how a completed Showdown is scored or counted.

## Proof
Add new numbered cases (keep every existing one) to `tests/firebase/closed-showdown-adapter-emulator.cjs` and `tests/firebase/completed-showdown-read-emulator.cjs`:
(a) Daniel creates a code, Nik never joins → Daniel's career is `ready`, the code is not counted;
(b) the same code then abandoned → still `ready`, not counted;
