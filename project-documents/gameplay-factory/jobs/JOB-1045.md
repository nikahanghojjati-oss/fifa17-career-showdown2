## Why
The workflows use major-tag actions, and they install the Firebase tools with `npm install --package-lock=false` and `npx --yes firebase-tools@...`. Both resolve fresh on every run. On 9 Oct express 5.3.0 was published at 12:56 UTC, and a CI install fetched it at 13:01 UTC and got a 404 on its tarball (PR #439, POS20 proof REMOTE).

## Change
1. In `.github/workflows/showdown-gate.yml` and `.github/workflows/gate-watchdog.yml`, pin every `uses:` to the full 40-hex **commit** SHA of the tag in use today, with the tag as a trailing comment (`uses: actions/checkout@<sha> # v5`). The tags are: actions/checkout v5, actions/setup-node v5, actions/setup-java v5, actions/cache v5, actions/upload-artifact v7 and actions/download-artifact v7. Dereference annotated tags to the commit. In the PR body, list each tag, its SHA and how you checked it (e.g. `git ls-remote https://github.com/actions/checkout refs/tags/v5^{}`).
2. Add an assertion to `tests/contracts/showdown-gate-coverage-contracts.cjs`, and to whichever Gate Physio or watchdog contract already parses `gate-watchdog.yml`, that every `uses:` in these two workflows ends in `@` plus 40 hex characters.
3. Only if it stays small: give the **Gate's own** Firebase tool installs a committed lockfile, for example `tools/gate-tools/package.json` plus `package-lock.json` installed with `npm ci --prefix tools/gate-tools --ignore-scripts`, using the same versions as today. Do NOT change `scripts/pos10-proof-runner.mjs`, any Validate POS20 workflow or any POS10/POS20 file. If the lock can't be applied without those, skip this step and list the commands that would need it.
