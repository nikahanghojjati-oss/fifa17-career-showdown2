## Background
The Showdown Gate is a CI check that runs in trial mode beside the old checks. Two pure functions accept evidence that should be refused. Both cases reproduce on `gameplay/bug-list-1` (same code as main e49add99):

```js
import {compareHead, evaluateExitCriteria} from './scripts/gate-compare.mjs';
import {LANE_IDS, LANES, selectedFor, evaluateSeal} from './scripts/showdown-gate.mjs';
const head='a'.repeat(40);
const c=compareHead({head,pos20:{verdict:'PASS',profile:'POS20_FULL_SEAL',ran:['x']},gate:{verdict:'PASS',profile:'OTHER_FULL_SEAL',ran:['x']}});
const canary={head:'b'.repeat(40),gate:{verdict:'FAIL_TEST',run_attempt:1}};
evaluateExitCriteria({comparisons:Array(10).fill(c),canaries:[canary,canary],infraRuns:[{run_attempt:2,watchdog_reruns:1,conclusion:'failure'}]}).ready; // true today, must be false
const route={profile:'POS20_FULL_SEAL',tests:[],proofs:[],operations:false};
const needs=Object.fromEntries(LANE_IDS.map(l=>[LANES[l].job,{result:'success'}]));
const lanes=Object.fromEntries(LANE_IDS.map(l=>[l,{schema:'showdown-gate-lane/v1',head_sha:head,lane:'WRONG',job:'WRONG',run_attempt:99,route_profile:route.profile,result:'success',selected:selectedFor(l,route),ran:selectedFor(l,route)}]));
evaluateSeal({event:'pull_request',draft:false,headSha:head,prLiveHead:null,route,needs,lanes,runAttempt:1,runId:100}).verdict; // 'PASS' today, must not be PASS
```

## The change
**`scripts/gate-compare.mjs`, `evaluateExitCriteria` (and the `--summary` CLI that feeds it):**
- Count unique heads only. Refuse incomplete comparison records (missing head, missing gate or POS20 verdict, or missing profile).
- Add a `same_route` criterion: every counted comparison has `same_route_profile===true`.
- `full_seals` counts only comparisons where the Gate verdict is PASS, the old verdict is PASS and the profile is a full seal.
- Canaries count unique heads only, each with Gate `FAIL_TEST` at `run_attempt===1`.
- Infra recovery needs `conclusion==='success'`, `run_attempt===2` and an automatic re-run attributed to the Physio. Do not derive `watchdog_reruns` from `run_attempt-1`. Read the attribution from the Physio's recorded results (see `scripts/physio-status.mjs` and the gate-watchdog results it reads). If attribution can't be found, that run does not count.
- Anything unknown or incomplete keeps `ready:false`. Keep `EXIT_CRITERIA` numbers unchanged.

**`scripts/showdown-gate.mjs`, `evaluateSeal` and the PR head lookup (about lines 235-251):**
- For a pull_request, an unavailable live PR head (lookup error or null) is a non-PASS verdict, e.g. `HEAD_UNKNOWN`, with a failure reason. Do not treat null as "not superseded".
- Each lane record must have `lane` equal to its slot, `job===LANES[lane].job`, the current `run_id`, and a `run_attempt` no greater than the current attempt. An earlier attempt is allowed only for the same run and head, when that lane's job result is success (a carried successful job).
- Add `run_id`, `base_sha` and a route digest (a sha256 of the canonical route JSON) to `buildLaneRecord` output, and check them in `evaluateSeal` against the seal's own values. Keep the lane schema name unless a bump is required; if bumped, accept only the new one.
- The user-facing cause text for infra verdicts should come from the classification reasons. Do not use a fixed "no machine" phrase.
