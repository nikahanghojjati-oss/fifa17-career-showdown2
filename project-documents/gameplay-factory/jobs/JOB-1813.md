## What to do
1. List the open pull requests whose title starts with `JOB-180`, `JOB-181` or `JOB-182` (jobs 1802 to 1829; skip JOB-1820, JOB-1822,

   `project-documents/gameplay-factory/status/REVIEW-PR-<number>.md` on branch `factory/gameplay-v1`. Take at most **2** PRs
   this turn (oldest first).
2. For each PR, read: its job file `project-documents/gameplay-factory/jobs/JOB-<n>.md` (branch `factory/gameplay-v1`), the PR
   body, and the PR's changed files (diff). At most 6 files per PR; if more changed, say so and review the 6 biggest.
3. Check, and answer each with PASS / FAIL / CAN'T TELL plus one line of evidence (file:line or a quote):
   - **A. Reproduced first:** the PR body shows the bug on the unchanged base (failing test output, CE2PG lines or screenshot).
   - **B. Cause named:** file:line plus quoted lines, and the quoted lines really are in the base at that place.
   - **C. Test fails then passes:** a new test was added, the body shows it failing on the base and passing after.
   - **D. Only allowed files:** every changed file is in the job's "Files you may change" (or the job's start section). List any other.
   - **E. No forbidden change:** no edit to existing tests, `index.html`, `service-worker.js`, `.github/`, `scripts/`,
     `tests/fixtures/`, `visual-assets/`, `firestore*.rules`, no new timer/interval/poll that reads online data, no shortened
     timer, no sessionStorage, no change to colours, sizes, positions or pictures (unless the job allowed one named selector).
   - **F. Logic is right:** read the fix line by line. Does it handle the no-shared-journey (solo) case, the reload case, and
     the "partner is ahead / behind" case the job describes? Name any input that would still give the wrong result.
   - **G. Checks pasted:** the job's *Checks* outputs are in the body and show PASS.
4. Verdict: **READY FOR CLAUDE** (A-G pass or only CAN'T TELL on G), **NEEDS FIX** (name exactly what), or **WRONG FIX**
   (explain why the cause or the fix is wrong).

## Write

and at most 5 lines of notes. Do not comment on the PR, do not push to the PR's branch, never merge.
