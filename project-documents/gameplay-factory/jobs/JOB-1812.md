# JOB-1812 · Free-limit message must show as soon as Home opens

| Lane | Release | Branch | PR into |

## The bug
When the free daily online limit is used up, the game is meant to say so in one plain line: "Today's free online limit is used
up. It resets at 3 am Boston time. Your saved career is safe." In r75 that line appears on Home only after the player taps a
tile; on a fresh Home it is missing, so a player sees nothing and thinks the game is broken.

## Where to start
The message and the "paused" state live in the "Firestore budget layer (r75)" at the end of `js/sparkPrivatePairing.js`
(`FSB_QUOTA_MESSAGE`, `fsbPaused`, `fsbQuotaMessage`, `fsbTrip`; the layer publishes `CareerModeFirestoreBudget`). Find how
other screens show it (search `quotaMessage` / `free online limit` in `js/`), and make Home show the same line, in the place
where Home already shows status text, as soon as Home opens while the pause is active, and when the pause starts while Home is
open (listen for the event the layer dispatches; add one if none exists). No new reads, no timer that reads Firestore.

## Test to add (must fail on the base)
`tests/contracts/free-limit-home-message-contracts.cjs`: in a vm sandbox (pattern: `tests/contracts/firestore-budget-contracts.cjs`,
which already trips the pause with a fake quota error), trip the pause, then open Home with a minimal fake DOM and assert the
line is shown without any tap; and trip it while Home is open and assert it appears.

## Rules
Use the existing text and the existing status element and styling; do not restyle (desktop Connect Players' small text is a
visual item for r77). `js/sparkPrivatePairing.js` is a pairing and sign-in file: change only the budget layer at its end; if
the fix needs the pairing part, stop and explain.

## Proof required
New test fails on the base, passes after; `node tests/contracts/firestore-budget-contracts.cjs` passes;
`node tests/browser/stage3-private-pairing-audit.cjs` and `node tests/browser/pairing-four-code-automation-audit.cjs` pass.

## Exact pointers (from Claude's standing-bug inventory of r75; confirm by reading)
Exact wiring today: the budget layer publishes the event `career-mode-firestore-quota` and the attribute `data-firestore-quota` (`js/sparkPrivatePairing.js:700-704`); the only subscriber is `js/onlinePlayerIdentity.js:56`; the message is shown by `report()` in `js/productionSharedJourneyEntry.js:44` only on a tap. Make Home react to the same event/attribute (no change needed in the budget layer itself). Files you may change: `js/productionSharedJourneyEntry.js` and/or the Home glue (`js/homeScreensV10.js` or `js/menuExperience.js`; keep `js/menuExperience.js` changes tiny, it is in the startup bundle), the new test, the two registration files.
