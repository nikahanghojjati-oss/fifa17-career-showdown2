## The bug
In a shared Showdown, after season 1 is committed, the Home Showdown tile and the header chip keep showing "Season 1 of N"
for the rest of the Showdown on both managers' screens. Seen in every CE2PG multi-season run on r74 and r75.

## Cause (found by Claude's CE2PG agent; confirm by reading)
`js/menuExperience.js:185` and `js/showdownUI.js:352` read the LOCAL `currentShowdown.currentRound`. In a shared Showdown the
local copy is not advanced by the partner's commit; the shared progression is (see `js/productionSharedMultiSeasonProgression.js`
and the shared journey marker `currentShowdown.sharedJourney`). Find the value the Season Results screen and the Standings use
for "season X of N" in a shared Showdown and use the same source here, falling back to the local value when there is no shared
journey (solo play must not change).

## Test to add (it must fail before the fix)
`tests/contracts/shared-season-chip-contracts.cjs`: load the two files in a `node:vm` sandbox with a minimal fake `document`
(only what the two functions touch) and a `currentShowdown` whose local `currentRound` is 1 while the shared progression says
season 3 of 5. Assert both the tile text and the chip text say season 3 of 5. Add a second case without a shared journey that
must keep using `currentRound`. Run it on the base first and keep the failing output for the PR.
