# JOB-1471 — Team V keyboard focus and reduced-motion audit (stage 1)

**Scope:** Static review of `css/v10Shell.css` (264 lines), `visual-assets/v10_1/shared/motion.css` (346 lines), and `visual-assets/v10_1/shared/showdown-ui.css` (197 lines) on `qa/mega-audits`. No browser, DOM walk, or unlisted screen files were inspected; these are source-backed risks, not a claim that every screen was interactively tested. **No game or frozen Team V file was edited.** Lead should bundle verified fixes in **`css/v10Shell.css`** only, scoped to `:focus-visible` and `prefers-reduced-motion` so touch/mouse appearance stays unchanged.

## Findings (8 maximum)

1. **Shared tab strip — missing explicit keyboard ring for unclassed tabs.** `visual-assets/v10_1/shared/showdown-ui.css:81-85,133-145` styles both `.sd-tab` and `.sd-tabs button`, but its focus-visible rule covers only `.sd-tab`. A `.sd-tabs button` without that class has no **kit-specified** ring (the browser default may still show). **Smallest fix:** in `css/v10Shell.css`, add `.sd-tabs button:focus-visible { outline: 2px solid var(--sd-gold-300, #f7d27a); outline-offset: 2px; }` (or equivalent visible high-contrast inset ring).

2. **Shared primary buttons / chip-tabs / tiles — clipped external focus outline.** `visual-assets/v10_1/shared/showdown-ui.css:56-65,81-85,90-104,145-150` combines `clip-path: polygon(...)` with an outside `outline-offset: 2px` focus outline on `.sd-btn`, `.sd-chip`, chip-mode `.sd-tab`, and `button.sd-tile`. Clipping can cut the external ring. **Smallest fix:** append a keyboard-only inset, high-contrast focus ring (e.g. `inset 0 0 0 3px var(--sd-gold-300)`) on those clipped elements in the shell, preserving any existing shadow. Verify in a browser because `clip-path`/outline behavior can differ by engine.

3. **Legacy History & Backup import zone — outline deliberately removed.** `css/v10Shell.css:229-233`: `.legacyImportDropZone:is(.dragActive, :focus-visible)` sets `outline: none` and only alters border/background, so the requested distinct keyboard ring is absent in this override. **Smallest fix:** add a separate `html[data-v10-tools] #legacy .legacyImportDropZone:focus-visible` rule with a visible `outline: 2px solid #f2c45b; outline-offset: 2px`, leaving `.dragActive` alone.

4. **Global shell non-kit controls — fallback ring not assured.** `css/v10Shell.css:97-101,129`: the Settings gear gets a hover/focus filter glow, while the sign-in overlay close button receives only a color rule; neither gets a **shell-defined focus ring** in the reviewed styles. Another stylesheet may provide one, so confirm this with keyboard navigation before treating it as a runtime failure. **Smallest fix:** add a shell-scoped `:focus-visible` outline for `.sd-nav .sd-nav-gear` and `#onlinePlayerIdentityOverlay button[aria-label="Close sign-in"]`, with no `:hover` changes.

5. **Primary action pulse still moves with reduced motion.** `visual-assets/v10_1/shared/motion.css:162-172,296-345`: `.sd-button-pulse.sd-is-pulsing` and `[data-sd-enter="button"].sd-is-pulsing` animate scale, but the reduce media query and attribute-based overrides do not list `.sd-is-pulsing`. **Smallest fix:** shell `@media (prefers-reduced-motion: reduce)` rule setting `animation: none !important; transform: none !important` for these active selectors; mirror if user-facing `html[data-motion-reduced="true"]` and `html[data-reduced-motion="true"]` modes are supported.

6. **Alternate data-attribute glint and count flash escape reduce overrides.** `visual-assets/v10_1/shared/motion.css:143-146,196-199,312-345`: the keyframes also apply to `[data-sd-glint="true"].sd-is-glinting::before` and `[data-sd-count].sd-count-leader.sd-count-complete::after`, while reduced-motion suppression names only `.sd-glint::before` and `.sd-count-up::after`. **Smallest fix:** add those two alternate selectors to the shell's reduce media block (and data-flag equivalents) with `animation: none !important; opacity: 0 !important`.

7. **Class-only entrances can bypass the 150 ms reduced fade.** `visual-assets/v10_1/shared/motion.css:65-72,155-159,296-311,326-334`: `.sd-character-in-left.sd-is-animating`, `.sd-character-in-right.sd-is-animating`, and `.sd-panel-rise.sd-is-animating` have active transform animations even without a `[data-sd-enter]` attribute; the generic reduced override requires that attribute. **Smallest fix:** in shell media and HTML reduce-mode blocks, target these three class-only variants with a short opacity-only fade (or `animation: none`); remove their translation/rotation and stagger delay.

8. **Shared interaction transitions remain enabled for reduce-motion users.** `visual-assets/v10_1/shared/showdown-ui.css:41-48,79-80,163,169-171`: feedback `transform`/transition effects remain on shared `.sd-btn`, `.sd-icon-btn`, `.sd-chip`, `.sd-tab`, checkbox boxes and toggle tracks/knobs. `motion.css` reduces choreographed entrances but does not govern these interactions. **Smallest fix:** in `css/v10Shell.css` within `@media (prefers-reduced-motion: reduce)`, scope `transition-duration: 0.01ms !important` (or `transition: none !important`) to these controls and their pseudo-elements. Preserve instant focus outlines and static selected states.

## Boundary and handoff

All eight are CSS-level findings against the three permitted files. The report does **not** assert that every Team V screen is covered or that the runtime reduced-motion setting is wired correctly; that would require a subsequent real keyboard and device-preference pass. Changes belong to a later Team G lead fix job, **not this reading audit**. Proposed rules go in `css/v10Shell.css` and should not change mouse/touch styling, game logic, screen ordering, or files under frozen `visual-assets/v10_1/`.
