# JOB-1780 · Shared Season Results audit

**Result:** one SURE bug fixed on `gameplay/audit-1780`. One new regression contract added and registered; existing tests left unchanged. Contracts await the Showdown Gate on the draft PR.

## Finding 1 — SURE
- **File and line:** `js/sparkSharedSeasonResults.js:60-64` (base `gameplay/bug-list-1`).
- **What the player sees:** A private session whose recorded expiry has passed can still be accepted by the Season Results provider if its stored state remains `active`. A player can try to view or publish shared season scores and winner results after the exact private connection should have expired.
- **Why:** The session check reads the expiration but only requires it to be finite:

  ```js
  const members=Array.isArray(value.data.memberAccountIds)?value.data.memberAccountIds:[],expires=ssrpTimestampMillis(value.data.expiresAt);
  if(value.data.rivalryId!==rivalryId||value.data.state!=="active"||members.length!==2||new Set(members).size!==2||!authorized.every(id=>members.includes(id))||!members.every(id=>authorized.includes(id))||!Number.isFinite(expires))ssrpFail("SEASON_RESULTS_ACTIVE_SESSION_REQUIRED");
  ```

- **Smallest change:** Add `||now>=expires` to the existing session validation before either reading or publishing Season Results. The function already receives `now` from the current provider request.
- **Regression:** `tests/contracts/chat-audit-spark-season-results-contracts.cjs` checks unexpired acceptance, rejection after expiry, and rejection at the expiry boundary. Registered in `POS20_SUPPLEMENTAL_PRODUCT_TESTS.json`.
- **Player-facing change:** No text, screen, tap order, points, scores, league-position tiebreak, or Showdown rules changed.
