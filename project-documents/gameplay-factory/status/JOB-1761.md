## Finding 1 · SURE · fixed
- File and lines: `js/backup.js:233-236`, `exportCareerModeBackup`.
- What the player sees: Exporting a backup just after updating a season score or a transfer draft can download a backup without that newest change; restoring it can show the older saved numbers. A failed pending write can also be followed by a misleading incomplete download.
- Why: Backup used the persisted snapshot immediately, even when scheduled application saves had not yet run. Original code:
  ```js
  async function exportCareerModeBackup(){
      const envelope = await createCareerModeBackupEnvelope();
      return downloadCareerModeBackupEnvelope(envelope);
  ```
- Smallest change: Before creating the envelope, invoke the existing `window.flushPendingApplicationWrites()` if present and reject on `false`. Reuse an existing failed-flush error string from restore. No gameplay, screen text, tap order or numbers changed.
- Test: Added `tests/contracts/chat-audit-backup-contracts.cjs` and the matching POS20 supplemental test registration. It models a scheduled score update and checks the exported checksum/score; a failed flush prevents the snapshot and download. Code and test re-read; automated execution is left to the Showdown Gate, Claude reviews the draft.

Adjacent checks: strict raw snapshot failure/warnings, complete Save Library payload/legacy/preferences counts, checksum verification, and download entry path. Existing `tests/contracts/backup-contracts.cjs` covers strict storage read failure, checksum, malformed records and provenance; those tests were left intact.
