## Three riskiest places checked

1. **Pre-write staleness check — `js/storageTransaction.js:39-84`.** The engine reads every requested slot, rejects mismatched expected values, and checks the exact snapshot or previously committed value again before each guarded write. A newer career should not be silently replaced by an older transaction.
2. **Partial write and verification — `js/storageTransaction.js:85-109`.** The engine records each accepted write, checks the post-commit raw values and enters rollback if any guard/write/verification fails. The production adapter maps raw keys through `js/storage.js` and returns false on local storage write errors.
3. **Rollback ownership and critical recovery — `js/storageTransaction.js:111-145`.** Rollback runs in reverse order, only restores values still owned by the transaction, then reads each rolled-back slot to verify. An intervening external change produces `rollback-failed-critical` instead of overwriting another save. Existing persistence contracts exercise quota failures, singleton retirement failures, stale cross-slot writes and ownership conflicts.
