## Finding 1 · SURE

- File and line: `js/productionSharedMultiSeasonProgression.js:143` (refresh), with the late read replacing the view at line 141.
- What the player sees: overlapping first reads after reload or reconnect can put an older accepted season count and older Showdown points back on the dashboard. In the reproduced case, a newly accepted season and its 3 points were replaced by zero accepted seasons and zero points.
- Why: the pending read is shared only when its key matches `contextKey`, but that key was only saved after the read completed. Before the first completion, another refresh starts a second read. Each response then replaces the view, including an older response arriving last.
- Source excerpts before the fix:

```js
if(refreshPromise&&contextKey===request.key)return refreshPromise;busy=true;
view=result;contextKey=request.key;
```

- Smallest change: set `contextKey=request.key` before starting the read in `pmspRefresh`. Overlapping refreshes for the same Showdown then share the pending read, including before the first view exists.
- Proof: the new plain Node contract failed before the fix with `0 !== 1` for accepted seasons when the older response arrived last. It passes after the fix and confirms carried Showdown points, ten ordered seasons, no season skipped by repeated Continue taps, and no season eleven.
