# JOB-1752 · js/screens.js second-half audit

## Finding 1 · SURE

- File and line: `js/screens.js:487-513` on `gameplay/bug-list-1`, `navigateTo`.
- What the player sees: When opening a screen waits for football presentation or gameplay loading, and the player makes a later navigation request, the earlier request can finish last and unexpectedly replace the newest chosen screen. This is repeatable with an earlier delayed Create Showdown request followed by Main Menu.
- Why the code does it (original excerpt, two lines):
  ```js
  await window.ensureRequiredFootballVisualExperience();
  ```
  ```js
  if(showScreen(target, addToHistory, options)){
  ```
  The older call shows its target after its await without checking whether a newer route request has already superseded it.
- Smallest change: Give each `navigateTo` request a monotonic request ID and return without showing anything if another request started before its screen is presented. Screen destinations, history choices, player-visible text and game rules stay unchanged.
- Fix branch: `gameplay/audit-1752`, based independently on `gameplay/bug-list-1`.
- Added exactly one regression contract: `tests/contracts/chat-audit-screens-b-contracts.cjs`, registered in `POS20_SUPPLEMENTAL_PRODUCT_TESTS.json`. The contract models out-of-order loading and requires the newest requested screen to remain visible. Code and contract re-read; execution left to Showdown Gate as required.
