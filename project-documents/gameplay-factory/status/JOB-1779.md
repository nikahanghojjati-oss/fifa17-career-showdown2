## Finding 1 — SURE
- **File and line:** `js/productionSharedShowdownSetup.js:190` (base branch `gameplay/bug-list-1`).
- **What the player sees:** If a private session expires or is replaced while a confirmed Shared Setup provider read is in flight, a failed read can leave Shared Setup marked **ready** for one additional refresh, even though the exact active session is gone. Its previously confirmed choices still appear available.
- **Why:** The provider-read failure hold checks only that a confirmed setup was previously ready; unlike the transient-context hold, it does not recheck the current private session:

  ```js
  if(readReached&&!/^SHARED_SETUP_(LOCAL_SAVE_MUTATION|STORAGE_AUTHORITY_UNAVAILABLE)$/.test(String(error&&error.code||""))&&!heldReadFailure&&state.ready===true&&state.setup&&state.setup.phase==="SHOWDOWN_CONFIRMED"){heldReadFailure=true;return setState({status:"ready",busy:false});}
  ```

- **Smallest change:** Add `&&heldSessionStillActive()` to this existing one-poll hold condition. This uses the module's existing exact session/authority/expiry guard, preserving one-poll recovery for an active session but locking after expiry.
- **Regression:** `tests/contracts/chat-audit-shared-showdown-setup-online-contracts.cjs` verifies an active-session read blip may hold once and that a session expiring during a failed read must lock immediately. Registered in `POS20_SUPPLEMENTAL_PRODUCT_TESTS.json`.
- **Player-facing change:** No text, layout, tap order, rules, season numbers, or saved choices changed.
