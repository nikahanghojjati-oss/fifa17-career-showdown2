## Finding 1 — stale tap can commit an earlier season
- **File and line:** `js/productionSharedSeasonCommit.js:164-166` (before fix: line 164 followed immediately by the write condition).
- **What the player sees:** After tapping **COMMIT & ACKNOWLEDGE SHARED SEASON**, a player who moves to another season while the commit read is still pending can still commit the earlier season. The older tap should not write after its on-screen season changes.
- **Why:** The pending provider read has no follow-up season-context check before the first write. Original lines:
  ```js
  const ctx=await psscProviderContext(request);if(!psscContextMatches(request))return false;let current=psscResultError(await provider.read(ctx.options));
  if(!psscSatisfied(kind,current)){if(!await psscWrite(kind,ctx,request,current))return false;if(kind==="commit")stage="acknowledge";current=psscResultError(await provider.read(ctx.options));if(!psscContextMatches(request))return false;}
  ```
- **Smallest change:** Add `if(!psscContextMatches(request))return false;` immediately after `provider.read` resolves and before any commit or acknowledgement write. Do not change screens, scores or text.
- **Confidence:** **SURE** — the read can be held while the current season changes, and the original code has no check on that path before calling `psscWrite`.
