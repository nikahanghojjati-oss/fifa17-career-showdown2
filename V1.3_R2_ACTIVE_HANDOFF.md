## First reproduced/evidence-backed r2 defects and fixes

1. Candidate A blocked-read ambiguity. `captureCareerModeRawBackupInputs()` uses lossy `readStorageValue()`, which converts a thrown `localStorage.getItem` into `null`. `backup.js` then treats the unread key as missing and can create an apparently valid incomplete backup. `captureCareerModeRawRestoreSnapshot()` already provides the exact fail-closed authority, so no new persistence authority is needed.

   Fix commit `5d57b30e0c3b4538f1e6b25275f5d4934cfd0e6f`: Candidate A now requires the strict exact raw restore snapshot and aborts if any canonical read is blocked.

2. Offline media reconnect stale-state clobber. r2 retained `menuMediaStatusBeforeOffline` after reconnect and restored it on every later online render without proving the offline override was still active.

3. Update activation race. r2 set `activationRequested=true` only after awaiting `CMS_ACTIVATE_UPDATE`; the waiting worker can call `skipWaiting()` and cause `controllerchange` before that continuation.

4. Redundant Service Worker registration. When an existing registration was found while online, r2 verified it but fell through to `navigator.serviceWorker.register()` again.

   Fix commit `10eab7986207c975e735ecc095857a3a2379584e`: reconnect restores only the actual offline override then clears its snapshot; update intent is armed before the activation message and cleared on rejection/no-waiting paths; existing registrations update in place and return before the new-registration path. No install UI or shell DOM was reintroduced.
