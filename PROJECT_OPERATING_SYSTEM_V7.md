# Career Mode Showdown Project Operating System v7

Status: candidate authority until reviewed and merged.

POS7 keeps POS6 Fast / Furious / Accurate and replaces broad risk-domain test selection with exact impact authority. The governing chain is:

`changed artifact -> affected invariant -> transitive consumer -> owning deterministic contract -> owning browser/emulator/deployment proof`

POS7 exists to make normal development faster without guessing about coverage. Unknown impact always makes validation broader, never narrower. POS7 itself earns zero SSJR and zero MDP credit.

## 1. Authority

1. Later explicit owner instruction.
2. Current verified source, live GitHub/provider/deployed state.
3. `CURRENT_PRODUCT_GUARDS.json`, executable release authority and current evidence models.
4. `POS7_IMPACT_GRAPH.json` for change-to-proof ownership.
5. `NEXT_TASK.md`.
6. Active PR recovery metadata.
7. A compact developer relay only at an intentional transition.
8. Git history for superseded process/provenance.

Never combine CI evidence across Git heads.

## 2. IMPACT-7 exact selection

`scripts/pos7-impact-router.mjs` is the executable selector and `POS7_IMPACT_GRAPH.json` is its machine-readable ownership graph.

For every changed non-document artifact, IMPACT-7 must either:

- resolve one or more directly affected invariants and all transitive consumers; or
- fail closed to `FULL_SEAL`.

Every current blocking deterministic contract must have exactly one invariant owner. Shared modules expand to all declared consumers. A test is never omitted merely because it is expensive.

## 3. Conservative escalation

The following always select `FULL_SEAL`:

- workflow topology;
- `package.json` or lockfile changes;
- current product guards;
- current product test manifest;
- the IMPACT-7 graph or selector;
- service worker or web manifest;
- deployment verification authority;
- missing changed-file evidence;
- any unclassified non-document artifact.

Provider/security changes expand through pairing, Connected Rivalry, Shared Setup and Remote Joining consumers. Canonical storage changes expand through Candidate C reconciliation, offline lifecycle, Shared Setup and dependent remote-session authority.

## 4. Proof ownership

Proof IDs are exact machine-owned units, not historical workflow labels. Current kinds are:

- deterministic contracts;
- browser proofs;
- Firebase emulator proofs;
- static/syntax proof;
- post-merge deployment proof.

`tests/support/run-selected-product-contracts.cjs` may execute only paths present in `CURRENT_PRODUCT_TEST_MANIFEST.json`. `scripts/pos7-proof-runner.mjs` may execute only proof IDs present in `POS7_IMPACT_GRAPH.json`.

The post-merge deployed Pages seal remains main-only authority; PR optimization must never replace deployed release proof.

## 5. Measured efficiency

Every route reports:

- selected deterministic contracts versus the complete census;
- selected heavy proofs versus the complete proof registry;
- selected modeled proof cost versus full-seal modeled cost;
- modeled heavy-proof cost saved percentage.

These are throughput measurements only. They never alter product scores and never justify skipping an affected invariant.

## 6. Current-product census purity

`CURRENT_PRODUCT_TEST_MANIFEST.json` remains the registry of blocking current deterministic product contracts. Historical/provenance, dormant/rejected architecture and process/continuity checks remain outside ordinary product validation.

The union of invariant-owned deterministic tests in `POS7_IMPACT_GRAPH.json` must equal the manifest exactly and contain no duplicate owners.

## 7. CWS-7 context-aware continuity

POS7 evolves CWS-6 by adding a weighted `contextSaturation` component. It must not invent a ChatGPT conversation ceiling and must not use account-plan or usage-limit logic.

When exact environment context capacity/remaining telemetry exists, CWS-7 uses that real remaining fraction. Otherwise it estimates saturation only from observable engineering signals:

- compaction/summarization events;
- reconstruction of already established state;
- loss of earlier exact details;
- repeated retrieval of facts that were previously live;
- volatile facts not yet represented in Git/PR metadata;
- unusually broad simultaneous reasoning state.

Context saturation is a transfer-risk signal, not a work-progress metric.

## 8. CWS-7 decisions and recovery

Recovery authority remains tiny active-PR metadata. One coherent atomic work unit may be active at a time unless parallel mutation is explicitly safe. No continuity-only commits or PRs are permitted.

Every completed substantive owner-facing response ends with:

`Continuity: <DECISION> · <SCORE>/100 · <short reason>`

Reads, successful tests, ordinary polling, message count, tool-call count and elapsed time do not create transition pressure by themselves.

## 9. Adaptive debugging

ADB-7 preserves POS6 failure-aware bounded correction budgets. Reads, diagnosis, polling, successful validation and an unreproduced infrastructure flake consume zero correction cycles. Diagnose the full coherent failure class before editing.

Broad product/security/context damage lowers correction allowance. Narrow test/process defects with healthy authority may receive a larger bounded allowance.

## 10. Product safety locks

`CURRENT_PRODUCT_GUARDS.json` remains machine authority.

Billing remains permanently OFF and Firebase remains Spark. Never enable Blaze, Cloud Billing/account linkage, Cloud Run or Cloud Functions. App Check enforcement remains OFF. Firestore browser persistence remains memory-only. Google Auth remains popup-only `browserSessionPersistence` with no extra scopes.

Exactly two private managers. Connected Rivalry pairing plus exact ACTIVE precedes league or club authority. Candidate C remains the sole destructive remote-to-local gameplay Apply authority with transaction-owned exact rollback.

Canonical local storage remains exactly `careerModeShowdown.saveLibrary`, `careerModeShowdown.legacyShowdowns`, and `careerModeShowdown.preferences`.

No public discovery/listing/lobby/matchmaking/community/rankings/global leaderboards. `SSJR-DUAL-FULL-SCREEN-1` remains permanent.

POS7 earns zero product credit. Once POS7 is reviewed, exact-head green and merged, operating-system work stops. Resume production Shared Setup integration/evidence immediately, then the next unfinished Shared Showdown capability.
