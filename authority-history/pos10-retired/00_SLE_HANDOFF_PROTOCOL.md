# Career Mode Showdown — SLE under Project Operating System v2

SLE = Smart Lean Efficient.

Status under POS v2: SLE remains a permanent working principle but the old multi-file mirrored packaging protocol is retired from normal engineering and from blocking product CI.

Current authority: `PROJECT_OPERATING_SYSTEM_V2.md`.

## Smart

Verify the live source boundary that matters. Distinguish current product authority from historical evidence. Fix meaningful product/safety defects instead of satisfying stale prose.

## Lean

A fresh environment starts from `00_DEVELOPER_START_HERE.md` and the five-file current startup set. Load historical handoffs, old bootstraps, context graphs and deep archives only when a concrete recovery or evidence question requires them.

Do not preload the entire project history.

## Efficient

Avoid duplicate test suites, repeated continuity publication, mirrored copies, version-number churn, history-of-history repair and owner chores that do not improve product correctness or recovery safety.

## Real handoff behavior

When POS-2 session health says a handoff is actually recommended, or the owner requests one:

1. finish or safely revert the current atomic operation;
2. run `npm run work:handoff-checklist`;
3. resolve the exact live repository/PR/head boundary;
4. record current task, blocker and next safe action;
5. create one compact successor snapshot that is sufficient to resume;
6. stop before starting a new substantial task if the current environment is no longer healthy.

A mirrored root/project handoff pair, new numbered START_NEXT_SESSION file, new numbered bootstrap, deep handoff, context-graph refresh and packaging-only commit are not automatically required. Create an additional artifact only when it provides unique recovery value for the actual transition.

## Historical compatibility

Earlier SLE starter/handoff/mirror files remain valid historical provenance in Git and archives. Do not rewrite or delete them just to conform to POS v2.

Legacy SLE packaging tests are retained by `npm run test:legacy-provenance` for intentional historical audits. They are not current product-release gates.

## Core rule

SLE succeeds when a successor becomes safely productive with less context and less process work, not when the repository accumulates more handoff files.
