## Practical-replica boundary

The owner reference is visual authority, not a flattened implementation artifact.

R8.33 intentionally does **not**:

- use the owner screenshot as the webpage background;
- bake navigation, tile labels or live state into an image;
- copy official league/club/trophy marks;
- import a proprietary game font;
- make the soundtrack artwork or waveform authoritative for playback;
- add a new backend, save write, Firebase call or network request.

Where the reference uses image-generated details, this consumer recreates the function with original DOM/CSS/SVG geometry. A later original stadium source-art ticket may replace the procedural atmosphere if it materially improves fidelity without baking UI into the background.

## State behavior

The proposal exposes two Home presentation modes only for deterministic QA:

- `resumable`: Continue Career is selected/gold;
- `no-resume`: New Showdown becomes selected/gold.

Focus or pointer selection moves the gold treatment to the focused/hovered tile, proving the requested selected-button language without changing product routing.

The media buttons are visual adapter controls in this isolated harness. They do not load or play network media.

## Remaining fidelity gap

R8.33 is materially closer to the owner target than R8.32, but it is still a browser-built approximation, not a claim of pixel identity.

The two largest remaining visual gaps are:

1. the reference uses a more painterly/high-frequency stadium atmosphere than the current procedural CSS stadium;
2. the reference headline has a stronger hand-painted brush-letter texture than system/browser fonts can reproduce reliably without a dedicated original lettering asset.

Those are now bounded source-art/design-system tasks. They do not justify returning to a primitive page layout or replacing the real DOM with an image.
