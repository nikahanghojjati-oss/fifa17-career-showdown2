# Surface Group 02 — Settings, Save Library and Local Profiles

Status: ACTIVE SURFACE CONTRACT

These surfaces use Level C clarity where identity, deletion or compatibility is involved, with Level B card presentation for ordinary saved-career browsing.

## Settings shell

Treat Settings as a modal control center, not a visual showcase.

Requirements:

- preserve current focus trap and focus restoration;
- remain comfortably scrollable on mobile;
- order panels by user dependency and risk rather than decorative novelty;
- keep destructive actions visually separated from ordinary preferences;
- no character artwork;
- no background animation behind identity or destructive controls.

If Save Library is mounted within the same shell, a title such as `SAVE LIBRARY & SETTINGS` is an acceptable proposal direction only if the final DOM/product language supports it.

## Save Library

Required state families:

- compatibility with existing legacy single-career format;
- empty library;
- blocked authority;
- ready library.

Ready Save cards may contain current product data such as:

- stable Save identity;
- Active Save / Local Save state;
- Showdown name;
- Manager 1 vs Manager 2;
- Not Started / In Progress / Completed status;
- season progress;
- League;
- Clubs;
- Last Played;
- Continue Active Showdown or Make Active;
- Delete This Save.

Presentation:

- card library, not a file explorer;
- active Save receives the clearest gold edge/status chip;
- progress remains semantically represented, not decorative-only;
- Delete This Save is visually separated and destructive;
- no official club crests;
- local-only truth remains explicit where applicable.

## Local Profiles

Stable identity and display label must remain visually distinct concepts.

Required presentation concepts:

- profile identity card;
- editable display label;
- stable short ID as secondary metadata;
- same visible names may remain separate stable profiles;
- cross-Save/historical identity linking is deliberate and advanced;
- never imply an automatic merge solely because labels match.

Canonical owner examples may show Daniel and Nik, but the live profile data remains product authority.

## Empty and blocked states

Empty Save Library must not show fake sample saves. Give a short explanation and appropriate next action if current product has one.

Blocked/compatibility states use clear amber/neutral hierarchy and explain why an action is unavailable. Red is reserved for actual destructive/error risk.

## Responsive contract

Desktop may use multiple Save cards per row and a compact profile grid.

Chromebook/tablet reduces columns before reducing type.

Mobile uses one Save card per row, keeps stable IDs wrap-safe, and ensures destructive actions do not sit immediately beside the primary Continue/Make Active control without separation.

## Asset resolution

No raster asset generation required.

Use DOM/CSS for Save cards, progress, identity chips and state panels. Add original local icons only if later QA proves scanability benefits.

## Accessibility and QA

- modal focus trap/restore preserved;
- stable ID is selectable/readable;
- progress is not color-only;
- delete controls are text-explicit;
- empty, blocked and loading states are distinguishable;
- long Showdown/manager labels wrap safely;
- duplicate visible display names never become an automatic identity merge cue;
- no character or decorative asset obscures controls;
- reduced motion has no effect on Save/identity authority.
